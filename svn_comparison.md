# Сравнение Git и SVN

### 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
* **В Git** ветка — это просто легковесный текстовый указатель (ссылка) размером около 40 байт на конкретный коммит. Создание новой ветки происходит мгновенно и локально.
* **В SVN** ветка создается как физическая копия каталога проекта на центральном сервере (`/branches/my-branch`). Это требует сетевого запроса к серверу и логического дублирования структуры папок.

---

### 2. Можно ли в SVN сделать коммит без интернета? Почему?
**Нет, нельзя.** 
SVN — это централизованная система контроля версий (CVCS). Вся история изменений и база данных репозитория хранятся исключительно на удаленном сервере. Поэтому любая фиксация коммита требует прямого соединения с сервером. В отличие от Git, у разработчика локально находится только рабочая копия файлов (Working Copy), а не локальный репозиторий.

---

### 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
1. **Работа с большими бинарными файлами и ассетами** (например, в геймдеве для 3D-моделей, графики, аудио), где Git начинает работать медленно из-за необходимости скачивать всю историю.
2. **Блокировка файлов (Pessimistic Locking / `svn lock`)** — возможность заблокировать файл от одновременного редактирования другими людьми, что критично для файлов, которые нельзя автоматически объединить (смержить).
3. **Гранулярный контроль доступа** — SVN позволяет настраивать права на чтение/запись для отдельных папок внутри одного репозитория, в то время как в Git права выдаются сразу на весь репозиторий.
